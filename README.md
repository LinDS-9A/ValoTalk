# ValoTalk —— 无畏契约国际服实时翻译

打国际服听不懂队友、自己不会用英文喊话、看不懂左下角聊天？这个工具一次解决：

| 链路 | 方向 | 结果 |
|---|---|---|
| **① 队友语音** | 游戏声音 → 语音识别 → 翻译 | **中文字幕出现在屏幕下方** |
| **② 我说话** | 手机点一下说中文 → 翻译成英文 → TTS 念出来 | 声音通过 VB-Audio Cable 送进游戏麦克风，**队友能听见英文** |
| **③ 左下角聊天** | 截屏 → OCR → 翻译 | 同一块字幕里显示中文 |

识别用本地 faster-whisper（不传云端），翻译走 Bing / Google / 你的 LLM，全离线也能跑（SAPI 兜底 TTS）。

> 🔴 **必须用管理员身份运行。** 无畏契约跑在 High 完整性级别，普通进程是 Medium，
> Windows 的 UIPI 会把 Medium → High 的模拟按键**静默丢弃**（`SendInput` 还照样返回成功），
> 结果是程序“按了 V”但游戏永远收不到，队友听不到英文。
> `run.bat` 已经会自动提权；用 `python -m valotalk` 手动启动时要自己开管理员终端。
> 原因和实测见 [§3.7](#37-为什么必须用管理员运行)。

---

## 1. 装

需要 Python 3.10+ 和 **VB-Audio Virtual Cable**（把 TTS 音频送进游戏麦克风的关键，免费）。

```powershell
powershell -ExecutionPolicy Bypass -File .\setup.ps1
```

脚本会：装依赖（阿里云镜像）→ 预下载 whisper 模型（hf-mirror）→ 跑环境自检。

启动：**双击 `run.bat`**（会弹一次 UAC，点「是」—— 原因见 §3.7）。

## 2. 游戏内设置（这一步不做，英文送不进游戏）

### 2.1 麦克风指向虚拟线缆

游戏 → 设置 → 音频 → 语音聊天：

| 项 | 设成 |
|---|---|
| 语音聊天输入设备 | **麦克风 (VB-Audio Virtual Cable)** |
| 语音聊天输出设备 | **你的耳机/扬声器**（**不要**选 Cable） |
| 语音聊天模式 | 见下 |

> ⚠️ 中文系统里 VB-Audio Cable 的两个端点名字是反的，别选错：
>
> - `扬声器 (VB-Audio Virtual Cable)` = **播放端**（默认名 `CABLE Input`），ValoTalk 往这里灌英文（面板上的「TTS 输出」）
> - `麦克风 (VB-Audio Virtual Cable)` = **录音端**（默认名 `CABLE Output`），游戏从这取麦克风（游戏里的「语音输入」）
>
> 有些机器上这两个名字被改过（比如「变声器输出」「变音麦克风」），认准括号里的
> `VB-Audio Virtual Cable` 就行；实在分不清就按默认名找 `CABLE Input` / `CABLE Output`。

**关于 Push to Talk：** 两种都行。

- **开放式麦克风（Open Mic）** —— 最省事，ValoTalk 一播就直接出去。
- **按键说话（Push to Talk）** —— 把键位绑到 `V`，ValoTalk 会在播放前自动按住 V、播完再松手（配置项 `tts.game_ptt_enabled` / `tts.game_ptt_key`）。

> 队友语音能被采集，靠的是扬声器回环（WASAPI loopback）。所以**游戏的语音输出必须是耳机**，一旦也设成 Cable，就会自己听自己。

### 2.2 显示模式必须是窗口化

游戏 → 设置 → 视频 → 显示模式：**窗口化全屏** 或 **无边框**。

独占全屏（Exclusive Fullscreen）下，任何浮层都画不上去，字幕会看不见。

### 2.3 建议把音效调小

队友语音和枪声、脚步混在同一条输出里。音乐/音效音量降到 40% 左右，识别率明显更好。

## 3. 用

双击 `run.bat`，出现控制面板：

1. **设备**三行会自动识别好，不对就手动选：
   - 游戏输出（采队友语音）→ 你的耳机
   - 我的麦克风 → 你的真实麦克风
   - TTS 输出 → **扬声器 (VB-Audio Virtual Cable)**（默认名 `CABLE Input`）
2. 点 **测试 TTS→游戏**，进游戏按一下语音键，能听见英文就通了。
3. 点 **框选左下角聊天**，拖一个框把聊天框圈住（Esc 取消）。
4. 顶部 **▶ 开始**（启动时会自动开始一次）。

### 快捷键（全局，游戏里也生效）

| 默认键 | 作用 |
|---|---|
| **按住 F2** | 说中文 → 队友听到英文（松开就翻译） |
| **F3** | 字幕窗在「穿透鼠标 / 可拖动」之间切换 |
| **F4** | 清空字幕 |
| **F5** | 临时静音英文输出（不想让队友听到时） |

**改键不用碰配置文件**：控制面板中间有「快捷键」一栏，四个下拉框选完立刻生效（会写回 `config.json`）。重复绑定、占用游戏开麦键 V 都会被拦下来并在日志里提示。

可选键位（23 个）：

```
F1 – F12
CapsLock、Tab、Insert、Home、End、Delete、PgUp、PgDn、`
MOUSE4、MOUSE5      ← 鼠标侧键（后退 / 前进）
```

两个约定：

- **字母键故意没开放** —— 打字、聊天时太容易误触
- **左右中键也没开放** —— 会干扰正常点击。只放鼠标侧键，因为 `GetAsyncKeyState` 能直接读到 `XBUTTON1/2`，当热键用是安全的

> 用鼠标侧键当触发键前，先看一眼游戏里这两个键有没有绑技能，避免按一下同时触发两件事。

字幕默认贴在**屏幕下方居中**。**字号和位置都能在面板上调**：

```
字幕  [A−] 19 [A+]    [↑][↓][←][→]  720,1060
```

| 控件 | 作用 |
|---|---|
| **A− / A+** | 字号减/加 1（范围 12–48），立刻重绘并在字幕窗弹一条预览 |
| **↑ ↓ ← →** | 位置微调，每下 20px，不会让字幕整个跑出屏幕 |
| 右边小字 | 当前坐标 |
| **字幕贴回下方** | 复位到屏幕下方居中 |

拖动也可以：按 **F3** 关掉穿透（或面板上关「字幕穿透鼠标」），直接拖字幕窗，
松手自动保存位置。

字号大了长句会折行，窗口高度是固定的（`overlay.height`），内容从底部往上堆，
超出就先丢最早的行。

### 游戏里热键不生效？用手机遥控

**结论先说：无畏契约里，任何程序的热键都不可能在游戏有焦点时收到。**

这不是本项目的 bug，是游戏的输入独占设计。三条路都试过：

| 方式 | 游戏有焦点时能否收到 | 说明 |
|---|---|---|
| `GetAsyncKeyState` 轮询 | ❌ 收不到 | 只在程序前台时有效 |
| `WH_KEYBOARD_LL` 低层钩子 | ❌ 被 Vanguard 拦 | 装了 Vanguard 就挂不上 |
| Raw Input `RIDEV_INPUTSINK` | ❌ 被游戏抢走 | 微软给后台程序的接口，但游戏优先 |

而窗口化无边框也没用 —— 问题不在显示模式，在输入通道。

**所以做了手机遥控**：手机走 WiFi，物理上绕开键鼠通道，怎么都拦不住。

#### 怎么用

**这个功能默认是关的**，在左侧「功能开关」区域打开：

1. 找到 **手机遥控当说话键** 那一行，点右边的开关（打开后变绿）：
   ```
   ● 队友语音 → 中文字幕        [●]
   ● 我说中文 → 英文语音（F2）   [●]
   ● 左下角聊天翻译              [●]
   ● 字幕显示原文                [●]
   ● 字幕穿透鼠标                [●]
   ● 识别用 CPU（不抢显卡）       [●]
   ● 手机遥控当说话键            [●]  ← 打开这个
       192.168.1.7:8765  [二维码]
   ```
2. 开关下面直接显示地址，点 **二维码**，手机（同一个 WiFi）扫一下就打开；也可以手动输入这个地址。
3. 手机上是一个大圆按钮，两种模式（按钮下方切换，会记住选择）：

   | 模式 | 操作 | 适合 |
   |---|---|---|
   | **按住** | 按住说，松手翻译 | 短促报点 |
   | **点按** | 点一下开始，再点一下结束 | **打起来两只手都要用鼠标键盘，推荐这个** |

4. 建议把网页「添加到主屏幕」，之后像开 App 一样点开，全屏没有地址栏。

按钮激活时会震动、变绿、并显示已按住的秒数。**按住模式超过 25 秒会提示松手**（识别有上限），点按模式不催你。

再点一下开关就关掉，端口立刻释放，地址行回到「未开启」，不用重启程序。

#### 手机连不上？

按顺序排：

| 现象 | 原因 | 办法 |
|---|---|---|
| 手机一直转圈 | **Windows 防火墙挡了** | 弹窗里点 **放行防火墙**（会弹 UAC，点「是」） |
| 提示「电脑那边没有响应」 | 地址不对 | 点二维码，弹窗底下会列出其他网卡地址，换一个试 |
| 连上了但按钮没反应 | 程序没点 ▶ 开始 | 手机页顶部圆点是灰的/红的就说明电脑那边没跑起来 |
| 手机锁屏后再按没反应 | 浏览器被系统挂起 | 页面试了 Wake Lock 防锁屏，仍是黑屏就关掉省电模式 |

手动放行（不想点按钮时，管理员 PowerShell）：

```powershell
netsh advfirewall firewall add rule name="ValoTalk Remote" dir=in action=allow protocol=TCP localport=8765 profile=any
```

> 规则用的是 `profile=any`。很多人 WiFi 被 Windows 判成「公用网络」，只放行 private 的话规则不生效、手机连不上还看不出原因。真正的访问控制是服务端的局域网来源校验。

#### 安全边界

- 只监听局域网：非 `127/10/172.16-31/192.168` 来源一律 403
- **默认自动生成口令**：第一次启动随机生成一串写进 `config.json` 的 `remote.token`，网址变成 `http://IP:8765/?t=口令`。二维码和「复制网址」都带着口令，扫一下就进去了，不用手打
- 为什么默认要口令：宿舍 / 校园 / 咖啡厅的 WiFi 在 Windows 眼里是**公用网络**，同一网段里谁都能扫到这个端口
- 想彻底不要口令（只在自己家、完全信任同网设备时）：
  ```jsonc
  "remote": { "enabled": true, "port": 8765, "token": "", "auto_token": false }
  ```
- 想换口令：改 `remote.token` 重启，旧二维码立刻失效
- 不想要了：`"remote": { "enabled": false }`，或者关掉防火墙规则

#### 掉线兜底

按住期间每 400ms 发一次心跳。**1.8 秒收不到心跳就自动松手**（并在日志里写一行），所以手机锁屏、切后台、WiFi 抖动都不会把「正在听」卡住不放。手机页面切到后台（`visibilitychange`）也会立刻结束本次说话。

### 3.7 为什么必须用管理员运行

这条踩了很久，写清楚免得再绕。

**现象**：程序应该替你按住 V 播英文，但游戏里麦克风图标从来不亮，队友听不到。

**实测数据**（`tools/keyinject_probe.py`）：

| 项目 | 值 |
|---|---|
| 本程序完整性级别 | `Medium (0x2000)` |
| `VALORANT-Win64-Shipping.exe` | `High (0x3000)` |
| `SendInput` 返回值 | **1（成功）** |
| 注入后能否读到 V | **否** |

`SendInput` 返回 1 是真的 —— 它成功把事件塞进了系统输入队列。但 UIPI
（用户界面特权隔离）在**投递阶段**发现目标窗口比调用方级别高，直接丢弃。
这个丢弃没有任何错误码，所以程序里看起来一切正常。

这是微软的既定设计：低完整性进程不能向高完整性窗口发输入。

**提权后**（`tools/keyinject_elevated_probe.py` 实测）：

```
管理员权限     : 是
本进程完整性   : 0x3000
游戏完整性     : 0x3000
注入会被拦吗   : 否
注入时前台 pid : 29900（VALORANT-Win64-Shipping.exe）
注入后读到 V   : 是          ← 进得去
```

**所以**：

- `run.bat` 会自动用 UAC 提权重启自己，你不用手动右键
- 用 `python -m valotalk` 启动的话，要在**管理员 PowerShell** 里跑
- 程序启动时也会自检：级别不够就在「设备」卡片里显示红字 + 一个「以管理员重启」按钮
- 想绕过提权（调试用）：`set VALOTALK_NO_ADMIN=1` 再跑 `run.bat`

**如果提权后还是不亮**，说明 Vanguard 也拦模拟输入。那就别跟它斗，改用开放式麦克风：

游戏 → 设置 → 音频 → 语音聊天模式 → **开放式麦克风**，然后

```jsonc
"tts": { "game_ptt_enabled": false }    // 不再模拟按键
```

麦克风常开，程序往 Cable 里播，游戏自动收走。效果一样，还少 0.5 秒延迟。

### 为什么说中文用 F2，不用游戏的 V

很多人第一反应是「V 不就是开麦键吗，为什么还要单独一个 F2」。因为这两个键在干**完全相反**的事：

| 键 | 谁按 | 作用 |
|---|---|---|
| **V** | **程序自动按** | 打开游戏麦克风，把英文 TTS 送出去 |
| **F2** | **你自己按住** | 告诉程序「现在开始听我说中文」，松手就翻译 |

程序播放英文之前会先替你按住 V、播完再松开（`tts.game_ptt_enabled` + `tts.game_ptt_key`）。你不需要手动碰它。

三个不能合并成同一个键的原因：

**1. 会自己触发自己。** 程序用 `SendInput` 注入 V，而热键是靠 `GetAsyncKeyState` 轮询的 —— 注入的键会被自己读到。播放完英文 → 被当成你又按了一次 → 再识别一遍 → 再播放，死循环。

**2. 游戏的开麦动作会插进来。** 你按 V 的瞬间游戏也在开麦，两条链路的状态互相打架。

**3. 语义相反。** V 是「我往外送声音」，F2 是「程序往里听我说话」。一个出、一个入。

#### 更省事的选择：用开放式麦克风

如果游戏语音模式设成 **开放式麦克风（Open Mic）**，就不用模拟按键了：

```jsonc
"tts": { "game_ptt_enabled": false }
```

麦克风一直开着，程序往 Cable 里播，游戏自动收走。**推荐这个** —— 没有按键时序问题，也不会偶尔和游戏抢键。

#### 想换触发键

**面板上直接改**：中间「快捷键」一栏，把「说中文」的下拉框选成 `CapsLock` 或别的，立刻生效，不用重启。

改完写回 `config.json` 的 `hotkeys.ptt`，想批量改也可以直接编辑文件：

```jsonc
"hotkeys": {
  "ptt": "capslock",
  "toggle_click_through": "f3",
  "clear_overlay": "f4",
  "toggle_mute_outgoing": "f6"       // 挪开，别和 ptt 撞
}
```

**只要别用 V**（那是游戏的），也别让四个键互相重复。

## 4. 模型怎么选（要不要 API key）

界面上有两处都叫「模型」，用途完全不同，先分清：

| | 开始按钮旁边的「模型」 | 翻译后端里的 `model` 输入框 |
|---|---|---|
| 是什么 | **本地语音识别**（Whisper） | **云端翻译**（qwen-plus / deepseek-chat 等） |
| 干什么 | 把队友的英文语音转成文字 | 把文字翻译成中文 |
| 跑在哪 | **你自己的电脑** | 阿里 / DeepSeek 的服务器 |
| **需要 key 吗** | **完全不需要** | **需要**（可选，不填也能用） |
| 花钱吗 | 免费 | 按 token 计费，约每万句几毛钱 |
| 体积 | 75 MB ～ 1.5 GB（首次下载，缓存在 `models/`） | 0，就是一次网络请求 |

**一句话：语音识别 0 个 key，纯本地离线跑；翻译可以配 LLM，不配也能用免费的 Bing。**

### 4.1 语音识别模型（Whisper，不需要任何 key）

**队友语音的语种由「游戏服务器」决定**，面板音频设备区有个下拉框：

| 选择 | 识别语言 | 适用 |
|---|---|---|
| **港/美服（英语）** | 英语 `en` | 港服、美服、大多数国际服 |
| **日服（日语）** | 日语 `ja` | 日服 |

> 俄服和韩服无畏契约没有，所以没做这两个语种。

实测两种模式：

| 服务器 | 队友说 | 识别 | 中文译文 |
|---|---|---|---|
| 港/美服 | `Enemy one tap on A site, watch the flank.` | ✓ 0.32s | 敌人包点一枪头，注意绕后 |
| 日服 | `Aサイトに敵、フランクに注意。` | ✓ 0.29s | A点有敌人，小心绕后！ |

日语模式会自动带上战术术语提示词，因为日语同音字极多——`敵`（敌人）和`適`（适合）都读 `てき`，不加提示会把「有敌人」听成「适合」，整句意思就废了。

日式术语也做了专门约束（`フランク=绕后`，不然会被译成人名「弗兰克」）：

```
Aサイトに敵、フランクに注意。  → A点有敌人，小心绕后！
Bサイトにスパイク設置          → B点下包
敵が一人残り、ローテート中      → 敌人还剩一个，正在转点
味方がエコー中                 → 队友经济局
```

#### 日服模式：识别和翻译都走大模型

选「日服（日语）」后，整条链路都跟着变，**而且切到大模型**：

| | 港/美服 | 日服 |
|---|---|---|
| 语音识别 | **本地** faster-whisper | **云端** `qwen3-asr-flash` |
| 翻译 | LLM 优先，失败降级机翻 | **只走 LLM**，不降级 |
| 我说的中文翻成 | 英语 | 日语 |
| TTS 音色 | 47 个英文音色 | 2 个日语音色 |
| 常用喊话直出 | 89 条英文 | 58 条日语 |

切到日服后，服务器那一行右边会显示 **`☁ 大模型识别 + LLM 翻译`**，日志里也会写明。

##### 为什么日服要换大模型

**机翻完全不懂日语游戏术语**，实测对比：

| 日语原句 | LLM 翻译 | Bing 机翻 |
|---|---|---|
| Aサイトに敵、フランクに注意。 | A点有敌人，小心**绕后**！ | 注意A点的敌人，注意**弗兰克** |
| オペレーター持ってる、出ないで。 | 我拿**大狙**，别出去。 | 我有**接线员，别接电话** |
| スポイク設置した。 | **炸弹已下** | 已安装**吸管** |
| 相手エコーだから、慎重に。 | 对面是**经济局**，小心点。 | 因为对方是**ECHO** |
| スパイク解除に行くから | 我去**拆包**，掩护我 | 我要去**解除尖刺** |

所以日服模式**只走 LLM**（`translate.backend` 设成什么都一样），
没配 LLM key 时会退回机翻并在日志里警告 —— 有错译文总比没有强。

##### 云端识别：可以接任意一家

**不绑定某个服务商**，改配置就能换：

| 服务商 | `cloud_provider` | 端点 | 备注 |
|---|---|---|---|
| **DeepSeek** | `deepseek` | `POST {base}/tools/asr` | 官方已支持 ASR，可复用翻译的 key |
| **阿里云百炼** | `dashscope` | 原生多模态接口 | `qwen3-asr-flash` |
| **OpenAI / 硅基流动 / 火山 / 自建** | `openai` | `POST {base}/audio/transcriptions` | 标准 OpenAI 兼容格式 |

```jsonc
// 用 DeepSeek（识别+翻译一套 key）
"asr": {
  "cloud_provider": "deepseek",
  "cloud_api_key": ""          // 留空则复用 translate.llm.api_key
}

// 用硅基流动的 SenseVoice
"asr": {
  "cloud_provider": "openai",
  "cloud_base_url": "https://api.siliconflow.cn/v1",
  "cloud_model": "FunAudioLLM/SenseVoiceSmall",
  "cloud_api_key": "sk-..."
}

// 用本机的 whisper-server
"asr": {
  "cloud_provider": "openai",
  "cloud_base_url": "http://127.0.0.1:8080/v1",
  "cloud_model": "whisper-1"
}
```

`cloud_provider` 留空时会按 `cloud_base_url` 自动判断（含 `deepseek` → DeepSeek，
含 `dashscope`/`qianwen` → 阿里云，其它 → OpenAI 兼容）。

**隐私说明**：云端识别会把音频发到**你配置的那个服务**，不是固定某家。
不想上传就把 `asr.backend` 设成 `local`，全部在本机识别。

##### 阿里云 vs DeepSeek 实测对比

6 条真实日语战术语句：

| | 阿里云 qwen3-asr-flash | DeepSeek |
|---|---|---|
| 识别延迟 | 352 ms | 399 ms |
| 需要术语纠正 | 2/6 | 2/6 |
| 翻译延迟（qwen-plus / deepseek-flash） | 0.91 s | 1.07 s |
| 翻译语义正确 | 6/6 | 6/6 |

**两家识别出的错误几乎一样**（都会把 `ウルト` 听成 `売ると`、`ローテート`
听成 `ロテート`），所以术语纠正表对两家都必要。选哪家看手头有哪个 key。

##### 延迟

实测（**关键是复用 HTTP 连接**）：

| 音频长度 | 首次（TLS 握手） | 之后 |
|---|---|---|
| 2.04s | 3.45s | 0.34s |
| 3.31s | 0.40s | 0.35s |
| 6.12s | 0.48s | 0.44s |

本地 whisper small 约 0.35s，所以**预热之后云端不比本地慢**。程序启动
（或切到日服）时会自动预热，第一句话不会卡。

##### 同音字纠正

大模型 ASR 也会听错，比如把 `ウルト`（大招）听成 `売ると`（会卖掉）。
`qwen3-asr-flash` 是专用 ASR 任务，**不支持传热词/上下文**（试过
hotwords / context / vocabulary / 文本提示，全部无效或被拒），
所以程序内置了一张确定性纠正表：

```
売ると → ウルト      スポイク → スパイク    ロテート → ローテート
エコ   → エコー      オペレタ → オペレーター  プランク → フランク
```

本地识别也走同一套纠正。实测 5 条日语句从 4/5 提升到 **5/5** 语义正确。

##### 想强制用本地

```jsonc
"asr": { "backend": "local" }
```

`backend` 三档：`auto`（默认，日服走云端）、`local`（始终本地）、
`cloud`（始终云端，英服也会用）。

云端失败时会自动降级到本地（`asr.cloud_fallback`，默认开），
日志里会有提示。

实测：

```
掩护我        → カバーして！
我开大了      → ウルト使う。
一波冲B       → Bをラッシュ！
他残血        → 残りHP少ない。
转点          → ローテート中。
我要去拆包，掩护我 → ボム解除に行くから、カバーして！   (LLM)
```

切换服务器时**音色会自动跟着换**（英→`en-US-GuyNeural`，日→`ja-JP-KeitaNeural`），下拉框也只剩该语言的音色，不会选错。

日语音色只有 2 个：`ja-JP-KeitaNeural`（男）、`ja-JP-NanamiNeural`（女）—— 这是微软 TTS 日语的完整清单。

**我说的话固定中文**（`lang_me = "zh"`），不受服务器选择影响。

| 模型 | 下载大小 | 显存占用 | 单句识别（GPU） | 单句识别（CPU） | 英文准确率 | 定位 |
|---|---|---|---|---|---|---|
| `tiny` | 75 MB | ~150 MB | 约 0.06s | ~0.5s | ~65% | 极限轻量，能听个大概 |
| `base` | 140 MB | ~250 MB | 约 0.12s | ~1.1s | ~78% | 轻量，偶尔错词 |
| **`small`（默认）** | **480 MB** | **~650 MB** | **0.25s（实测）** | 4.6s | ~87% | **平衡点，推荐** |
| `medium` | 1.5 GB | ~1.5 GB | 约 0.6s | ~14s | ~92% | 准，但吃显存、延迟高 |

> 「单句识别」指 3 秒左右的语音片段。`small` 的 GPU/CPU 数字是实测值，其余按模型规模推算。

**怎么选：**

| 遇到什么 | 改成 |
|---|---|
| 保持默认 | `small` |
| 字幕延迟明显（超过 2 秒） | `base` |
| 识别经常错字、影响理解 | `medium` |
| 游戏掉帧（显存不够） | `base` 或 `tiny` |
| 勾了「识别用 CPU」 | 必须 `tiny` 或 `base`（CPU 跑 `small` 比说话还慢） |

`tiny`/`base`/`small`/`medium` 都是多语言版。Whisper 还有英语专用版（`tiny.en`/`base.en`/`small.en`），同样大小但英文更准、快 10~20% —— 如果只用来听英文队友，换成 `.en` 版更划算，把 `config.json` 的 `asr.model` 改成 `small.en` 即可。

### 4.2 翻译模型（可选 key，不配也能用）

走四级降级：**LLM（若配置）→ Bing → Google → MyMemory**。

**免费通道（不需要任何 key）**

| 通道 | 需要什么 | 延迟 | 质量 | 说明 |
|---|---|---|---|---|
| **Bing** | 无 | 0.6–1.2s | 中 | **国内直连，默认首选** |
| Google | 需要梯子（填 `translate.proxy`） | 快 | 中上 | 有代理时质量比 Bing 略好 |
| MyMemory | 无 | 8–12s | 差 | 最后兜底，慢到影响体验 |

**云端 LLM（需要 key，质量最好）**

| 服务 | base_url | model | 延迟 | 备注 |
|---|---|---|---|---|
| **通义千问** | `https://dashscope.aliyuncs.com/compatible-mode/v1` | `qwen-plus` | 0.7s | **实测推荐**，语境最自然 |
| 通义千问（更快） | 同上 | `qwen-turbo` | 0.4s | 快一点，质量略降 |
| DeepSeek | `https://api.deepseek.com/v1` | `deepseek-chat` | 0.5–1s | 便宜，质量好 |
| 硅基流动 | `https://api.siliconflow.cn/v1` | `Qwen/Qwen2.5-7B-Instruct` | 快 | 免费额度多 |

**本地 LLM（不需要 key，文字不出本机）**

| 服务 | base_url | model | 备注 |
|---|---|---|---|
| Ollama | `http://127.0.0.1:11434/v1` | `qwen2.5:7b` | 完全不联网，吃本机显存/内存 |

**质量差距有多大**（同一句实测）：

```
LLM:   A点敌人一枪头，小心侧翼！
Bing:  敌人一次击杀在A点，小心侧翼。（one tap=一枪头，flank=绕后）
```

机翻需要用术语表注释来救场，LLM 本身就译对了。

#### prompt caching（省输入 token）

`system` prompt 里有整套术语表（约 560 tokens），每句翻译都要重传。把它标记成可缓存后，服务端会复用，命中的部分按低价计费。

配置里已经默认开启：

```jsonc
"translate.llm": { "prompt_cache": true }
```

实测对比（`qwen-plus`，prompt 565 tokens）：

| 设置 | 命中缓存 | 命中率 |
|---|---|---|
| 关闭 | 384 tokens | 68% |
| **开启** | **448 tokens** | **79%** |

> 通义千问**本身就会自动缓存**（不标记也命中 384），标记后多命中 64 tokens。
> 延迟没受影响（499~619ms）。
>
> 如果哪个兼容接口不认 `content` 数组格式，代码会自动退回纯字符串重试一次，不会因为加了这个参数把翻译搞挂。

按 1000 句算，省下约 0.06 元——**基本可以忽略**，属于顺手优化。

#### DeepSeek 的思考模式必须关掉

如果 LLM 用 DeepSeek，**一定要关思考模式**——程序已经自动处理，这里说明原因。

DeepSeek 默认 `thinking` 是开的（文档：不传就等于 enabled）。翻译是短句，
思考纯属浪费，而且会出两个问题：

| 配置 | 平均延迟 | 返回空结果 |
|---|---|---|
| 默认（思考开着） | 1.35 s | **1/4 条空** |
| `thinking: {"type":"disabled"}` | **0.48 s** | **0/4** |

返回空的原因是：思考内容占满了 `max_tokens`（`finish_reason=length`），
正文一个字都没输出，用户看到的就是空白字幕。

代码在 `_via_llm` 里固定带 `"thinking": {"type": "disabled"}`，
不认这个参数的接口（比如通义）会 400，自动去掉重试一次。
万一还是被思考吃掉了配额，会放宽 `max_tokens` 再来一次。

### 4.3 隐私去向

| 数据 | 去哪 |
|---|---|
| 你的语音、队友语音 | **只在本机**（Whisper 本地推理），不上传 |

### 4.7 TTS 音色与风格（队友听到的声音）

面板「音频设备」最下面两行：

```
TTS 音色：[Emma | 美 | 女 | 开朗清晰 ▾]
风格预设：[萝莉音 ▾]   [试听]
```

**47 个英文音色**，覆盖 14 个地区：美 / 英 / 澳 / 加 / 爱尔兰 / 印度 / 新西兰 / 南非 / 菲律宾 / 新加坡 / 香港 / 肯尼亚 / 尼日利亚 / 坦桑尼亚。下拉框里标了地区和性格，比如 `Ana | 美 | 女 | 可爱`。

**7 个风格预设** — 自动搭配音色 + 音高 + 语速：

| 预设 | 音色 | 音高 | 语速 | 效果 |
|---|---|---|---|---|
| 原声（不调） | 保持不变 | +0Hz | 不变 | 只复位音高 |
| **萝莉音** | AnaNeural | **+35Hz** | +15% | 稚嫩高音 |
| 正太音 | BrianNeural | +25Hz | +12% | 少年感 |
| **御姐音** | AriaNeural | **−20Hz** | −5% | 成熟低沉 |
| 大叔音 | ChristopherNeural | −25Hz | −8% | 厚重沉稳 |
| **气泡音** | ChristopherNeural | **−35Hz** | −12% | 低沉拖音（英文无真气声，靠音高模拟） |
| 青年音 | BrianNeural | +5Hz | +8% | 轻松随意 |

**「试听」按钮** 合成一句 `Enemy one tap on A site, watch the flank.`，**直接播到你的耳机**（不是 Cable），点完立刻听到。

音高由 `tts.pitch` 控制（`+35Hz` / `-20Hz` 这种），缓存按「文本 + 音色 + 音高 + 语速」分开存，改任何一项都会重新合成，不用手动清。

#### 关于「机械感」

这些是**微软 Azure 神经网络音色**，不是老式 SAPI 那种一字一顿的机器人音，基础音质接近真人录音。

但队友仍会觉得「不像真人」，原因不在音质：

| 来源 | 说明 |
|---|---|
| 没有情绪起伏 | 念固定文本，语气平；真人喊战术会带急迫感 |
| 语速均匀 | 每个词等长；真人会在重点词加重 |
| 游戏语音压缩 | 无畏契约用 Opus 约 24kbps，削高频，「电话里的人」感 |
| 节奏接不上 | 你说完约 2 秒后英文才出来 |

想更像真人：换 `AndrewNeural` 或 `EmmaNeural`、把 `tts.rate` 降到 `+0%`、用 LLM 把措辞翻得更口语。

## 5. 性能（本机实测，RTX 4060）

各模型的速度、准确率、显存占用完整对比见上面 **4.1 语音识别模型**。这里只列关键的 RTF 指标：

| 配置 | 单句识别 | RTF | 能不能用 |
|---|---|---|---|
| **small + GPU（当前默认）** | **0.23–0.31s** | **0.10** | ✅ 实时 |
| small + CPU | 4.6s | 1.76 | ❌ 比说话还慢 |
| base + GPU | ~0.12s | ~0.05 | ✅ 更快，准确率略降 |
| tiny + GPU | ~0.07s | ~0.03 | 抢答用，错字多 |

> GPU 加速要求 `nvidia-cublas-cu12` + `nvidia-cudnn-cu12`（已装好，约 1.2GB）。
> ValoTalk 启动时会自动把它们的 `bin` 目录注入 DLL 搜索路径；缺库会自动退回 CPU 并在日志写明，
> 失败的设备会被记住 7 天，不会每次都白等一遍。

**端到端延迟**（队友说完 → 屏幕出现中文）：

```
安静环境：VAD 收尾 0.24s + 识别 0.25s + 翻译 0.7s ≈ 1.19s
枪战环境：VAD 收尾 0.42s + 识别 0.25s + 翻译 0.7s ≈ 1.37s
```

**VAD 收尾会自动跟着环境走**（`audio.vad.adaptive_gap`，默认开）：

| 背景 | 噪声 RMS | 收尾等待 | 切出的语音 |
|---|---|---|---|
| 纯静音 | 0.000 | **240 ms** | 完整，不丢字 |
| 安静 | 0.004 | **240 ms** | 完整，不丢字 |
| 一般 | 0.015 | 360 ms | 完整，不丢字 |
| 枪战 | 0.050 | 480 ms | 完整，不丢字 |
| 爆音 | 0.080 | 480 ms | 完整，不丢字 |

以前是固定的 380ms——实测不管 0.000 还是 0.080 的噪声，切段延迟**全是 480ms**
（安静时白白多等 240ms）。现在安静场合省掉这 240ms，枪战时保持原来的稳健度，
不会因为等得太短把话切断。

原理：每轮算「非语音部分」的 RMS 当环境噪声（只看最近 0.8 秒，不然枪声停了
还认为在打仗），对数插值成等待时长（200ms ↔ 420ms）。噪声估计用非对称 EMA
（变大慢、变小快）并限速，避免枪声一来等待时长猛跳。检测到语音快说完时会切到
120ms 的加急轮询——实测 CPU 占用不变（1.4% → 1.4%）。

想手动调：

```jsonc
"audio": { "vad": {
  "adaptive_gap": true,      // 关掉就回到固定 silero_end_gap_ms
  "gap_min_ms": 200,         // 安静时等多久
  "gap_max_ms": 420,         // 枪战时等多久
  "noise_quiet_rms": 0.005,  // 低于此视为安静
  "noise_loud_rms": 0.055,   // 高于此视为枪战
  "noise_smooth": 0.15,      // 噪声估计的 EMA 系数
  "check_fast_ms": 120       // 快说完时的加急轮询间隔
} }
```

想更快：把 `gap_min_ms` 再降到 160，或者翻译换成本地 LLM。

模型面板右上角可直接切换（tiny/base/small/medium），换完自动重载。

### 资源占用（影响游戏帧数，已优化）

| | 优化前 | 优化后 |
|---|---|---|
| CPU（单核当量） | **1236%** | **107%** |
| 整机 CPU（24 线程） | 51.5% | **4.5%** |
| 内存 | 813 MB | 800 MB |
| GPU 显存 | ~0.5 GB | ~0.5 GB |

元凶是 **onnxruntime 默认 `intra_op_num_threads=0`＝有多少核用多少核**：一次 OCR 墙钟只有 178ms，却吃掉 2822ms CPU（16 个核一起上），每 0.6 秒来一次就是 4.7 个核常驻。

现在的做法：

- onnxruntime 强制 `intra_op_num_threads=2`、`inter_op=1`、`ORT_SEQUENTIAL`
- whisper `cpu_threads=2`
- 聊天 OCR 间隔 600ms → **1200ms**
- Silero 分析窗口 12s → **8s**
- 进程优先级降到 **Below Normal**，游戏永远优先拿到时间片

想再省一点：把「左下角聊天翻译」开关关掉，OCR 是剩下的大头；或者 `asr.compute_type` 改 `int8_float16` 省显存。

### 帧率影响（60–200 横跳怎么解决的）

实测排除了两个常见嫌疑：

| 嫌疑 | 实测 | 结论 |
|---|---|---|
| mss 截屏读回显存 | 30 次抓取，中位 5.6ms，最大 11.4ms，无一次超 20ms | 不是它 |
| whisper 抢占 GPU | 单次推理 GPU 峰值 51%；连续 6 次里 **0% 的时间显卡被占满** | 不是它 |

真凶是**字幕窗口本身在打断全屏合成**：分层透明窗口每 500ms 调一次 `SetWindowPos` 置顶，会破坏全屏游戏与显示器可变刷新率的同步，帧率就在刷新率上限和 60 之间反复跳。

| 改动 | 之前 | 现在 |
|---|---|---|
| 置顶检查间隔 | 500ms | **3s**（且只在有新字幕时额外置顶一次） |
| 描边层数 | 8 层 | **4 层** |
| canvas 元素数 | 90 个（9 条 × 10） | **35 个**（6 条 × 6） |
| 字幕窗口高度 | 380 | **300** |
| 聊天 OCR 间隔 | 1200ms | **2000ms** |
| 面板电平刷新 | 40ms（每秒重排 25 次） | **200ms**（每秒 5 次） |

还加了个彻底的开关：**「识别用 CPU（不抢显卡，稍慢）」**。勾上之后识别完全退出显卡，游戏独占 GPU。注意 CPU 上 `small` 很慢（RTF≈1.8），勾了要同时把模型换成 `base` 或 `tiny`。

如果还掉帧，按这个顺序排查：

1. 关掉「左下角聊天翻译」→ 还卡说明不是抓屏
2. 勾上「识别用 CPU」→ 还卡说明不是显卡
3. 把 `overlay.max_lines` 调成 3、`outline` 设 `false` → 还卡说明不是字幕窗口，检查是不是游戏本身或驱动
4. `overlay.backdrop` 设 `true` 换回黑底（不透明窗口的合成开销远小于分层透明）

### 6.1 聊天 OCR 速度档（`ocr.onnx_threads`）

面板「聊天区域 & 翻译后端」卡片里有一行 **OCR 速度**：

```
OCR 速度  [平衡（650ms） ▾]
          墙钟越短越快，CPU 占用越高
```

| 档位 | 值 | 墙钟（参考） | CPU 总量 | 建议核心数 |
|---|---|---|---|---|
| **省 CPU（829ms）** | `1` | 慢 | 最低 | 任何机器，4 核以下首选 |
| **平衡（650ms）** | `2` | 中 | 中 | **默认**，6 核以上 |
| **最快（625ms）** | `4` | 快 | 最高 | **8 核以上** |

原理：`onnxruntime` 的线程数。线程越多墙钟越短，但 CPU 总量成倍涨
（同步开销 + 缓存失效）——实测 4 线程的 CPU 总量是 1 线程的 4.8 倍。

#### 会不会卡？（实测掉帧数据）

拿一个 busy 线程模拟游戏渲染（每帧 16.67ms 里干 10ms 活），
**故意把 OCR 也设成 Normal 优先级**（最坏情况，实际 ValoTalk 是 Below Normal）：

| CPU 核心 | 1 线程 | 2 线程 | 4 线程 |
|---|---|---|---|
| **4 核** | 0 丢帧 | **丢 3 帧**（最长 37ms） | **丢 3 帧**（最长 32ms） |
| **6 核** | 0 丢帧 | 0 丢帧 | **丢 7 帧**（最长 41ms） |
| **8 核** | 0 丢帧 | 0 丢帧 | 0 丢帧（最长 21ms） |
| **24 核** | 0 丢帧 | 0 丢帧 | 0 丢帧（最长 17ms） |

所以：

- **8 核以上**：随便选，4 线程档完全无感
- **6 核**：别用 4 线程档（会明显卡），用平衡档
- **4 核及以下**：只能用省 CPU 档

程序会**按你的核心数给建议**：核心数不足 8 时，选 4 线程档会在日志里警告，
面板提示也会标注建议档位。但不强制限制，你仍可以选。

> 表里的毫秒是参考值，实际取决于聊天框大小和 CPU 型号。切换档位会重建 OCR
> 引擎，下一句识别会稍慢一下，之后就稳定了。

### 6.2 聊天 OCR 频率与空闲退避

- `interval_ms`（默认 2500）：有新消息时的扫描间隔
- `idle_backoff_max`（默认 4）：连续没有新消息时，间隔按倍数拉长，最多 4 倍
  （2500 → 10000ms）。一出现新行立刻回到正常节奏

为什么要退避：一次 OCR 要 0.6~0.9 秒墙钟，聊天框大部分时间是静止的，
按固定 2 秒扫就是白烧 CPU（实测占 46%~127% 单核）。

字幕样式：

- `font_size` 字号（像素），范围 12–48，面板上 A−/A+ 就是改这个
- `x` / `y` 字幕窗位置，`-1` 表示自动（居中 / 贴底），面板方向键改这个
- `backdrop` 黑色底板，默认 **关**；关掉后靠 `outline`（8 向描边）保证在亮背景上也看得清
- `show_original` 是否在译文下面显示英文原文（小一号灰字）
- 想让字幕更高或更宽，改 `height` / `width`，内容永远从底部往上堆

改完重启 `run.bat`。面板上改的项会立刻存盘。

## 7. 排障

先跑：

```powershell
python -X utf8 tools\probe_env.py
```

| 现象 | 原因 / 处理 |
|---|---|
| 队友说话没字幕 | 面板里「游戏输出」选错；或游戏语音输出走了 CABLE。先看日志有没有 `采集队友语音`，再看有没有 `队友：... → ...` |
| 字幕不出现但日志有内容 | 游戏是独占全屏；或字幕窗跑到屏幕外——点「字幕贴回屏幕下方」 |
| 说中文没反应 | 用**手机遥控**（游戏里键盘热键进不去，见 §3）；或麦克风选错；模型还在加载（看日志「模型」行） |
| 手机打不开网页 | 防火墙没放行 → 点「二维码」→「放行防火墙」；或手机不在同一个 WiFi |
| 队友听不到英文 | **先确认是不是管理员运行**（§3.7，最常见原因）；再查 TTS 输出是不是「扬声器 (VB-Audio Virtual Cable)」/`CABLE Input`；游戏麦克风是不是指向「麦克风 (VB-Audio Virtual Cable)」/`CABLE Output`；`tts.game_ptt_key` 和游戏里的语音键是否一致 |
| 英文念得断断续续 | 把 `audio.capture_samplerate` 改 44100 试试；或换 `tts.engine: "sapi"` 走离线 |
| 翻译失败 | 日志里 `translate` 那行；Bing 偶尔限流，配 LLM 最稳 |
| 识别全是乱七八糟 | 音乐音效太大；换 `small` 以上模型 |
| 播报自己又被识别 | 游戏语音输出别设 CABLE；或用 F5 暂时静音 |

其他：`asr.device` 写 `"cuda"` 但没装对 CUDA，会自动回落到 CPU（日志里能看到 `cpu / int8`）。

## 9. 软件内更新

启动 4 秒后自动查一次新版本（后台线程，不打扰使用）。有新版会弹窗：

```
🎉 发现新版本
v2.1.2  →  v2.1.3

更新内容
┌──────────────────────────────────┐
│ - 软件内自动更新：启动时检查…    │
│ - 更新走 jsdelivr CDN…           │
└──────────────────────────────────┘
   [下次再说]  [立即更新]
```

- **下次再说**：记住这个版本，下次启动不再弹（出现更新的版本才会再提示）
- **立即更新**：显示进度条 → 下载 → 覆盖 → 变成「立即重启」，点一下自动重开
- **手动检查**：点标题栏的版本号 `v2.1.2` 也能查

更新**只覆盖** `valotalk/`、`run.bat`、`README.md`、`CHANGELOG.md`，
不动 `config.json`、`models/`、`cache/`、`logs/`。覆盖前会自动备份到
`cache/update/backup/<旧版本>/`，出问题可以拷回来。

### 为什么不走 GitHub API

| 途径 | 实测 |
|---|---|
| `api.github.com` | 未认证每小时只有 **60 次**配额，被限流就查不到版本 |
| `github.com` | 部分网络**直连超时**（本项目实测不通） |
| `cdn.jsdelivr.net` | **通**，走 CDN，不限流 |

所以统一走 jsdelivr。更新包也放在仓库 `dist/` 里（`dist/ValoTalk-vX.Y.Z.zip`），
下载一个 zip 比逐个拉源码快 15 倍（实测 4s vs 65s）。zip 下不到才降级逐文件。

配置项：

```jsonc
"update": {
  "enabled": true,
  "check_on_start": true,        // 关掉就不自动查
  "skipped_version": ""          // 点过「下次再说」的版本
}
```

## 10. 已知行为

- **启动时会有一次采集异常**（`'bytes' object has no attribute 'size'`），设备刚打开时的瞬时问题，之后 12 秒压测 100% 稳定，可以忽略。
- **字幕延迟 ≈ 1.2s**（安静）/ 1.4s（枪战），主要花在「等你说完」的静音判定上。自适应默认开着，安静时只等 240ms；想更激进就调小 `audio.vad.gap_min_ms`，但容易把一句话切断。
- **7.1 虚拟声卡**（7.1 耳机/虚拟声卡很常见）采集时只取 L/R，直接对 8 声道取均值会把前场人声衰减 4 倍。
- **首句识别会慢**：模型第一次加载约 30s（含 GPU 转换），之后就绪了。面板右上角切模型会自动重载。
- **聊天只翻玩家说的话**：必须带「名字: 内容」前缀才算聊天。`Spike has been planted`、`Round 5`、`Enemy remaining: 2`、`XXX joined the party` 这类系统广播整行丢掉，不占字幕位。
- **字幕无黑底**，改用文字描边（8 向 1px）。如果觉得在深色场景下不够清楚，把 `overlay.backdrop` 设 `true` 换回黑底。
- **翻译失败时字幕只显示英文原文**，不会静默丢掉。
